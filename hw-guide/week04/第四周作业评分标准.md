# 第四周作业评分标准：项目长期记忆与混合检索

版本：1.0

整理日期：2026-11-20

满分：100 分

## 1. 适用范围与评测目标

本标准用于批改“AI Agent 全栈工程师训练营”第四周作业，以[作业说明](AI%20Agent%20全栈工程师训练营-作业四.md)为依据，结构沿用第三周评分标准。作业没有附带练习源码和原始测试。题目没有写明的实现细节，按第四周课程（4.3 Memory、4.4 RAG、4.6 项目四）讲授的规则解释，不把课程演示里的可选做法写成新的扣分门槛。

评测目标是确认两件事。第一题确认：换一个会话以后，Agent 能复用已经写入并核对过的项目知识；记忆支持写入、按项目查找并读取、更新和删除，记录落在持久化存储里，而不是只留在当前会话。第二题确认：资料变多以后，能从同一批节点建立向量索引和关键词索引，分别用向量、BM25 和 RRF 混合检索找到证据，再由真实模型生成带来源的回答；资料更新后，两路索引同步，旧分块退出当前检索。

采用源码核查、学员提交的运行记录和截图核对、以及教师补跑相结合的方式。不能仅凭 README 声明、截图上的结论句或已有的 passed 报告判断完成，也不能用截图数量直接换算分数。截图必须能和实际保存路径、命令输出或索引文件相互印证。

## 2. 核心验收前提

- 第一题的写入、查找并读取、更新、删除四个动作都有实际实现，并且已经接到当前项目的 Agent、工具或课程插件上。只提交一份静态笔记、没有程序入口，不算完成。
- 记忆写入的是持久化存储。关闭当前会话、再启动全新会话后，不靠聊天记录仍能读到该项目的记录。
- 第二题使用 Python 和 LlamaIndex，基于同一批节点建立向量索引和 BM25 关键词索引，并保存索引。
- 向量索引使用真实 Embedding，不是随机向量、哈希向量或写死的假向量。
- 同一问题分别完成向量、BM25 和 RRF 混合检索；混合检索的证据交给真实模型，生成带来源引用的回答。
- 在作业资料副本上把登录会话有效期改为 20 分钟后，两路索引都已同步，旧分块退出当前检索，新回答和新引用使用新资料。
- 两题都提交了可运行代码，以及题目要求的三类记录。第一题是建库结果、查询对比与回答、更新后的回答。第二题是建库结果、三路查询对比与回答、更新后的回答。截图可以是这三类记录的载体，但不能代替可复现的命令和输出。

具体缺陷按对应验收项判定。已确认核心前提失败，结论为“未通过”。仅截图或三类记录缺一项、引用没有指到具体分块，或删除后的残留不影响读取时，在其他核心前提成立的条件下判为“通过，需修复”。未验证事项按“证据不完整”处理。已确认核心失败时，不因同时存在未验证项而改判。

作业等级统一按[学员作业反馈报告模板与要求](../学员作业反馈报告模板与要求.md)第二节，只按总分确定：优秀为 80 分及以上，良好为 60 分及以上、低于 80 分，不及格为低于 60 分。不另设分数封顶或一票否决规则。

内部评测附件另记录验收结论，不改变按分数确定的作业等级：

| 结论 | 判定条件 |
| --- | --- |
| 通过 | 核心前提全部成立，两题的行为、索引和提交记录均有可复现证据，没有需要修复的缺陷。 |
| 通过，需修复 | 核心前提全部成立，但截图或记录缺一项、引用没有指到具体分块，或删除后存储里仍留有不影响读取的残留。 |
| 证据不完整 | 受缺失代码、凭据、模型或 Embedding 不可用等因素影响，部分能力尚不能验证；给出暂评分及补交要求。 |
| 未通过 | 已确认核心前提不成立，如记忆不能跨会话读取、四动作缺一、没有使用 LlamaIndex、两路索引不是同一批节点、Embedding 不真实、三路检索缺一路、混合回答没有真实模型，或更新后旧分块仍被当前检索返回。 |

“未验证”不等同于“已确认错误”，也不等同于通过。对可确认部分暂评，列明未验证项及其待定分值，补充证据后复评。核心缺失必须写入学员反馈的不足和改进方案。

### 2.1 判分依据与范围

- 题目写明记忆“可以由工具或课程插件提供，不强制使用特定工具名称，不要求接入向量数据库”。因此 `memory_remember`、`okf_remember`、`/okf-init` 或其他名称均可。OKF、YAML front matter、`index.md` 和 `log.md` 是课程推荐的组织方式，不是扣分门槛。自建的 JSON、SQLite 或 Markdown 存储，只要能按项目持久化并完成四个动作，按行为判分。
- 第一题的目标项目是课程中的 `login_demo`。学员改用结构等价的登录会话项目时，按同一行为判分，但记录里必须写明实际项目路径、测试入口和测试说明的位置。教师按学员记录的路径复现，不要求路径与课堂演示的 `~/.pi/agent/okf-memory` 相同。
- 题目中的 Shell 代码块是交给 Agent 的任务说明，不是要求学员在终端手打的固定命令。评测看 Agent 或工具是否完成这些动作，以及保存路径、核对结果和更新结果是否真实。
- “按项目查找并读取”指按当前项目隔离后查找，再读取命中记录的正文。只在回答里提到文件名、没有实际读取，不算读取。不同项目的记忆不能串到当前项目。
- 更新必须改原来的记录，而不是只追加一条与旧记录并列、且旧记录仍作为当前事实被读出的新记录。旧内容可以留在历史说明里。
- 删除后，按项目查找不再返回该记录，新会话也不能再读到它。允许软删除，但软删除的记录不能继续当作当前记忆返回。
- 第二题的“登录资料”指 `login_demo` 项目中可被检索的登录说明、规则或源码。学员可以索引课程 `4-4/corpus` 或自己整理的副本。只索引与登录会话无关的通用文档，不能用来证明本题。
- “同一批节点”指向量索引和 BM25 索引使用同一批分块，分块标识能够对应。两路各切一次、节点集合对不上，不满足这项。
- Embedding 供应商和模型不限定。课程演示过 MiniMax `embo-01` 和 `BAAI/bge-small-zh-v1.5`，二者都算真实 Embedding。必须记录模型名和向量维度，并且维度与实际向量长度一致。
- BM25 实现不限定。LlamaIndex 的关键词检索、`rank_bm25` 或其他 BM25 实现均可，只要查询的是同一批节点。用普通子串包含代替 BM25，不算关键词索引。
- RRF 按名次融合，不把向量分数和 BM25 分数直接相加。融合参数 `k`、两路权重和候选数量由学员声明；作业没有指定数值，不因与课堂的 `k=60` 或 `0.7/0.3` 不同而扣分。
- 作业写了两处结果数量：说明文字要求展示各自的前三条结果，Shell 说明要求输出各自前5条结果及来源。两处同时出现，展示不少于 3 条即可；学员展示 5 条不扣分，也不额外加分。回答引用的证据必须来自当次混合检索结果。
- 向量库不限定 Milvus。LlamaIndex 支持的持久化向量存储均可。作业没有要求重排、查询重写、元数据过滤、PDF 解析、Cross-Encoder、Elasticsearch 或固定问题集评估，这些只作为亮点或建议，不追加分数，也不因缺少而扣分。
- 真实模型只要求用于混合检索之后的回答生成。建索引、三路检索和更新索引不要求调用对话模型。第一题不要求真实模型，除非学员选择用 Agent 会话完成记忆动作；此时仍以存储和跨会话读取为准，不以模型回答措辞为准。
- 本评分标准是批改用的分值分配方案。作业没有要求单独 README、依赖锁文件、自动化测试或指定截图格式，不因缺少这些文件本身扣分。能按提交材料复现验收即可。

### 3.2 扣分原则

- 同一根因不重复扣分。例如记忆只存在于当前会话的消息列表，导致新会话读不到，主要扣“全新会话读取”；不要再把同一次失败算作写入、查找和更新三项全失。
- 一个子项最多扣至零分，总分最低为零、最高为 100。只有独立缺陷才能分别扣分。
- 比例扣分保留精确值参与计算。中间子项不逐项舍入。汇总后仅对总分按十进制四舍五入保留两位小数（ROUND_HALF_UP），该值作为正式总分，同时用于等级判定和报告展示。例如 79.994 分记为 79.99 分、良好，79.995 分记为 80.00 分、优秀；59.994 分记为 59.99 分、不及格，59.995 分记为 60.00 分、良好。内部保留原始分值与计算式；明细展示值如因舍入与总分有尾差，应注明，不调整实际扣分。
- 每次扣分记录触发条件、预期结果、实际结果、证据位置、所属子项和分值。
- 行为缺陷扣对应模块。截图或记录缺失，但教师已经复现该行为时，只扣提交记录中尚未覆盖的那一项，不把同一行为再扣一遍。
- 教师补跑发现的缺陷扣对应模块，不再因“学员记录没暴露”另扣提交记录分。
- 没有使用 OKF、pi 插件、Milvus、MiniMax、BGE、重排或查询重写，本身不是扣分理由。超出范围的完善只作为亮点或建议，不追加分数。

## 4. 统一验收用例

### 4.1 环境与提交材料

记录学员仓库、分支、提交号、Python 版本、LlamaIndex 版本、Embedding 模型名和向量维度，以及第一题实际使用的 Agent 或插件版本。按学员说明的入口复现，不改学员业务代码。

第一题先确认实际保存路径。在该路径读取存储内容，确认它不在会话临时目录里，并且进程退出后仍然存在。然后按学员给出的方法关闭会话、启动全新会话，再执行查找和读取。

第二题在学员项目中复现建索引、三路查询和更新。需要真实 Embedding 或对话模型时，只使用学员提交的配置或评测环境中已有的 DeepSeek 官方接口。没有可用凭据时，把对应调用标为未验证，不把环境阻塞直接写成代码缺陷。

学员可以增加脚本或测试。教师不能只凭学员截图认定通过；截图与复跑不一致时，以复跑为准。

### 4.3 建议边界补测

可补测：写入时来源缺失、查找词只能命中标题不能命中正文、更新时原记录不存在、删除不存在的记录、两路节点标识有一部分对不上、混合结果不足 3 条时如何展示、资料副本里同时保留 30 分钟和 20 分钟两段时回答是否指出冲突。

这些用例用于定位实现问题。题目没有要求的扩展只写建议，不新增扣分门槛。若补测证明按项目隔离、原记录更新或旧分块退出这些明确要求不成立，按对应子项扣分。

## 5. 关键判分口径

### 5.1 长期记忆的存储与会话

- 持久化指进程和会话结束后记录仍在。把记录只放进当前模型上下文、内存字典或会话临时文件，M2 不得分。
- 全新会话必须是新的会话标识或新进程，不能只是同一会话里再发一条消息。学员用 pi 时，关闭后重新启动 pi 即满足。学员用自建 Agent 时，新进程且不加载旧会话消息即满足。
- 读取必须有证据。工具回执、存储查询日志或教师直接查看存储都可以。回答里出现了正确路径，但存储里没有这条记录，不算读取成功。
- 来源至少要说明这条路径和命令是从哪个文件或哪次命令得到的。课程里的 `source: session` 只是一种写法。没有来源时扣 M1 的来源部分，不因此否定整条写入。
- 项目隔离按学员声明的项目键判断，可以是仓库根目录、项目名或知识包目录。没有项目键、所有项目共用一份当前记忆时，M3 不得分。

### 5.2 核对与更新

- 核对的是当前文件，不是复述记忆原文。记录写着某路径、该路径已经不存在时，仍回答“已核对一致”，M4 不得分。
- 题目要求把会话测试迁移到 `tests/auth/test_session.py`。这是制造项目变化的指定结果，不是建议路径。更新后的当前路径必须是这一路径；只在回答里说“已迁移”而存储仍是旧路径，更新不得分。
- 测试说明必须同步修改。只改测试文件、记忆里的说明仍指向旧入口，更新子项最多得部分分。
- 新测试命令应实际运行，并把通过、失败或未能运行的结果写入更新后的来源。环境缺少依赖而未能运行时，记录必须写明原因，不能把未运行写成已通过。写明原因并完成路径更新的，更新子项扣 3 分；伪称通过的，更新子项不得分。
- 旧命令可以出现在历史说明中。它若仍出现在当前入口、当前路径或新会话读到的当前事实里，更新不得分。
- 删除和更新是两个动作。只更新不删除，或只删除不更新，分别按对应子项扣分。

### 5.3 分块、Embedding 与两路索引

- 登录资料至少要覆盖能回答有效期问题的文档或源码。课程语料中的当前事实是 30 分钟，来源包括 `docs/session-rules.md` 和 `app/session.py`。学员使用其他登录资料时，以该资料的原文为准，不要求引用这些文件名。
- 分块样例必须能定位来源，例如文件路径、标题或行号。只打印一段没有出处的文本，样例部分不得分。
- 节点数量要和实际入库数量一致。打印一个硬编码数字、与索引中的节点数不符时，该项不得分。
- 真实 Embedding 指调用了学员声明的 Embedding 模型，并且索引中的向量维度等于该模型的输出维度。用全零、随机数或词哈希代替向量，Embedding 子项不得分。
- 同一批节点用节点标识核对，不以“两边都建了索引”代替。允许 BM25 存在进程内对象，但必须随建库保存，新进程能重新载入；只在建库进程的内存里查询、没有保存，保存子项不得分。
- 分块策略不限定。按标题、按句子或按固定窗口都可以。作业没有要求 Overlap、AST 分块或保留 PDF 页码。

### 5.4 三路检索与回答

- 三路必须分开展示。只给混合结果、没有向量和 BM25 各自的前若干条，缺的那一路不得分。
- 每条结果至少含名次或顺序、片段和来源。来源要能回到资料中的位置。
- RRF 的输入必须是同一问题在两路上的排序。把两路分数归一化后相加，不算 RRF，融合子项不得分；两路结果本身仍可得分。
- 作业没有规定 RRF 的 `k` 和权重。学员必须在代码或记录中写明所用参数。参数缺失但不影响复现命令时，只在评语中建议，不扣分。
- 真实模型回答必须能对应到当次混合检索返回的证据。引用了一份没有进入当次结果的文件，或者回答的分钟数在所引用分块中不存在，回答子项不得分。
- 模型凭参数记忆回答出 30 分钟、但引用对不上当次证据，不算通过。检索结果不足以回答时，模型应说明证据不足；把证据不足说成已引用证明，同样不得分。
- 没有可用的对话模型凭据时，R4 标为未验证，不把检索部分判失败。Fake Model 或手写答案不能代替 R4。

### 5.5 资料更新

- 必须改作业资料副本。直接修改课程原件或学员仓库里唯一的一份资料，导致无法对照旧结果时，副本子项不得分；若两路索引和新回答仍能证明 20 分钟已生效，其余子项按证据给分。
- 20 分钟必须写进被索引的资料，而不是只在查询参数或提示词里告诉模型。只改提示词、索引仍是 30 分钟，更新不得分。
- 两路都要更新。只重建向量索引、BM25 仍返回旧分块，同步子项不得分。
- “旧分块退出当前检索”指当前向量、BM25 和混合结果都不再返回那条仍写着旧有效期、且被当作当前事实的分块。旧分块留在备份索引或历史目录里可以。软删除后仍被任一当前查询返回，本项不得分。
- 资料里若同时保留 30 分钟和 20 分钟，回答必须引用 20 分钟那条作为更新后的当前资料，并指出冲突。只回答 20 分钟、引用却仍是旧分块，新回答子项不得分。
- 课程 4.6 讲的是资料与源码冲突时以代码为准。那是 Agent 使用检索结果时的规则，不是本题的索引更新规则。本题以更新后的作业资料为准。

## 6. 证据要求与批改流程

每次评测记录学员版本、评测日期、Python 与 LlamaIndex 版本、Embedding 模型和维度、实际项目路径、执行命令、退出码，以及第一题的保存路径。每个扣分点记录最小复现与对应子项。

1. **固定对象**：记录仓库、分支、提交号或提交包，不直接修改学员业务代码。
2. **核对范围**：确认第一题针对登录会话项目，第二题索引的是该项目的登录资料。
3. **复现记忆**：按第 4.2 节执行 M1 至 M6。M2 和 M6 的读取必须使用新会话或新进程。
4. **复现检索**：按学员入口建索引并保存，核对节点标识和向量维度，再跑三路查询。
5. **核对真实回答**：确认 R4 的模型调用真实发生，引用来自当次混合结果。
6. **复现更新**：在副本中修改有效期，重建或增量更新两路索引，确认旧分块退出。
7. **按根因评分**：使用第 3 节逐项计分，避免重复扣分；给出验收结论及待修复要求。
8. **留存附件并出具反馈**：完整证据保存在内部，给学员的报告按统一模板提炼重点。

日志与示例不得包含真实凭据。教师补跑使用的密钥只放在评测环境，不写入评测附件。

## 7. 扣分示例

| 问题 | 建议处理 |
| --- | --- |
| 记忆写在当前会话消息里，新会话读不到 | “全新会话读取”不得分。若存储本身不存在，写入子项一并按未持久化扣；不另扣查找。验收结论未通过。 |
| 保存路径返回了，但该路径没有记录正文 | 写入子项不得分。截图上的路径不能单独作为通过证据。 |
| 新会话只在回答中提到文件名，没有读取回执，存储里却有记录 | 跨会话读取不得分，写入分保留。 |
| 所有项目共用一份记忆，另一个项目也能查到 | 按项目查找不得分。写入和更新若独立成立，不重复扣。 |
| 更新时另写一条新记录，旧记录仍作为当前路径被读出 | 更新不得分，验收结论未通过。 |
| 删除后存储里还有标记，但查找和新会话都不再返回 | 删除给满分。残留只在评语中建议。 |
| 没有使用 LlamaIndex，自己用脚本切块后写入向量库 | 分块与 LlamaIndex 子项不得分。若因此无法确认同一批节点，同一批节点子项再按证据扣。验收结论未通过。 |
| 两路各自切块，节点标识对不上 | 同一批节点不得分，验收结论未通过。 |
| Embedding 向量是随机数 | Embedding 子项不得分，验收结论未通过。检索若因此无意义，三路检索按未验证或按实际结果扣，不与 Embedding 重复扣同一根因。 |
| 只展示了混合检索前 5 条，没有单独的向量和 BM25 结果 | 向量和 BM25 两路不得分，RRF 和回答按已有证据给分。 |
| 三路都只打印了前 2 条 | 从三路结果子项部分扣分，不判核心前提失败。 |
| RRF 把余弦相似度和 BM25 分数直接相加 | 融合子项不得分。两路检索分保留。 |
| 回答写出 30 分钟，但引用的分块没有这一数字 | 回答子项不得分。三路检索分保留。 |
| 没有真实模型，手写了带来源的答案 | R4 不得分，不能用 Fake Model 替代。其余核心前提成立时，验收结论为通过，需修复。 |
| 直接修改唯一资料，没有副本；更新后的索引和回答仍一致指向 20 分钟 | 副本子项不得分，其余更新子项按证据给分。 |
| 只重建了向量索引，BM25 仍返回 30 分钟分块 | 同步子项不得分，验收结论未通过。 |
| 旧分块仍出现在当前混合结果里，回答却说 20 分钟 | 旧分块退出不得分；新回答按引用是否使用新资料另判。 |
| 没有 OKF、Milvus、重排或自动化测试 | 原题未要求，不扣分。 |

示例用于统一尺度，实际扣分以证据和子项上限为准，不能机械叠加。

### 8.2 发给学员的反馈报告

按[学员作业反馈报告模板与要求](../学员作业反馈报告模板与要求.md)的结构、条数、字数和排版要求出具，并通过其第五节检查。

- **等级**：按第 3.2 节舍入后的正式总分确定，与评测附件一致，示例为 `作业等级：良好（79.00分）`。暂评分应明确标注，并使用相同精度规则。
- **优点**：选取已验证的跨会话读取、双索引和更新后检索。截图齐全应说明核对过的范围，不等同于真实 Embedding 或真实模型已验证。
- **不足**：按影响排序，合并同一根因。明确区分缺陷与未验证事项。没有足够独立问题时不凑数。
- **改进方案**：与不足对应，写明修复动作和复验条件。题目外的建议（如 OKF、重排、固定问题集评估）注明不影响得分，并排在必须修复事项之后。
- **内部留存**：详细评分表、验收结论标签、命令、日志和复现步骤保留在评测附件，不放入简明学员反馈。
