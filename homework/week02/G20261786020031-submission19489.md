# 第二周作业反馈

学员：问。（G20261786020031）

**1. 作业等级：不及格（43分，暂评）**

当前仓库实现与本周原题契约明显不同，请先核实提交链接及版本；本次只评价当前提交，不沿用旧分。

**2. 作业优点**

- 当前项目的 27 项自带离线测试通过；原提交演示可运行，能打印转账确认、脱敏结果和关联审计。
- 原生账户模型下，匹配审批可完成转账；满余额转出正确归零，一次性审批重放会被阻止。
- 原生预检在审批前检查租户归属和余额，缺失账户、跨租户及余额不足时不改变余额，邮箱和敏感字段递归脱敏有效。

**3. 作业不足**

- 固定的 `PermissionEngine.decide()` 已被重写，原题运行入口及结果接口也不同。可信五测全部在初始化时受阻，不能据自带测试通过认定原题验收通过。
- 账户初值、账号格式及金额契约不符：当前使用 `acc_1001` 等嵌套账户、Decimal 和 10000 上限，并额外必填 reason；数值字符串可通过，原题三个合法参数反而被拒绝。
- 未实现教学拦截区间，余额不足及缺失目标的错误码不符；正式注册 handler 没有按大额触发三秒休眠，演示中的另建慢工具不能代替该要求。
- 返回值缺少题定 txn_id/from/to，金额为字符串且状态为 completed；权限名不是 transfer:execute，canonical_target 未区分转出、转入和金额，题定 ACC 账号也未按要求脱敏。

**4. 改进方案**

- 先确认是否交错版本；以本周原始练习为基线，恢复固定权限引擎和可执行验收接口，不修改原测断言，重跑可信五测。
- 恢复四个模拟账户及浮点余额，按题定正则、严格 float 与 `(0,100000]` 定义三个字段；补测数值字符串拒绝及金额边界。
- 在预检中实现教学区间和余额错误码；在正式 handler 中完成缺失目标拒绝及扣款前大额休眠，再验证超时与余额不变。
- 对齐返回字段、权限名、目标参数区分和 ACC 账号掩码；保留当前确认与审计展示，并用原题成功、审批绑定、重放用例复验。
