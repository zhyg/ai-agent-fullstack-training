# 第一周作业反馈

学员：G20250805010079

**1. 作业等级：良好（77分）**

**2. 作业优点**

- 同一入口能按 `model` 路由到 `chat-fast` 和 `chat-pro`。未知模型返回 `unknown_model` 400，不会静默换成默认模型。
- 两个真实模型的普通调用和流式调用都成功。流式响应是 `text/event-stream`，内容分块到达，并有 `response.completed` 结束事件。
- 结构化结果在返回前会做 JSON 解析和 Schema 校验。非法、空、截断 JSON 以及类型不符都会返回明确错误，围栏和夹杂说明文字也能修复后再校验。
- 模板可按版本引用，变量会替换后再进入模型请求。缺模板、缺版本、缺变量都返回 400，不会把未替换占位符发给模型。
- 每次调用都有 `call_id` 可关联。失败调用也会入账。可重试错误有次数上限和指数退避，400 不会反复请求。限流超限返回 HTTP 429，窗口过后配额能恢复。

**3. 作业不足**

- 两个模型实际都走 Chat Completions。README 也写明本期只做这一种上游协议，没有第二种协议的请求路径和响应解析。
- 作业要求的 `response_format` 在统一入口被 422 拒绝。OpenAI 兼容入口可以翻译该字段，但 `chat-pro` 配置的 `json_schema` 被上游拒绝后，网关返回 502，两个模型不能都通过统一入参拿到结构化结果。
- 限流按调用方分桶，不按模型分桶。`chat-fast` 耗尽额度后，同一调用方的 `chat-pro` 也被 429 拒绝。
- 已向客户端输出内容后，如果上游流没有成功终态就结束，网关仍记为成功并发出完成事件。指数退避的正向抖动也会让等待超过当次上限。
- 推理 Token 有字段但适配器不读取，真实调用中推理用量被记成 0。按 README 安装后，原测试命令因缺少 `pytest-asyncio` 无法运行异步用例，README 也没有可运行的 curl 示例。

**4. 改进方案**

- 为第二个模型增加真正不同的上游协议，例如 Responses 或 Anthropic Messages。用抓到的请求路径和请求体证明两种协议不同，再分别做普通、流式和结构化调用。
- 让统一入口接受 `response_format`，并映射到各协议的实际写法。上游不支持 `json_schema` 时返回明确 4xx，或降级为 `json_object` 加本地校验；不要把上游 400 收成 502。
- 限流改为按模型，或按调用方加模型分桶。耗尽一个模型后，另一个模型仍应能调用；超限继续返回 HTTP 429，并补一条配额恢复用例。
- 上游流出现错误事件或没有成功终态时记为失败，不要补发成功终态。退避抖动后的等待不要超过当次 `min(cap, base·2^(n-1))`。同时读出并记录推理 Token，未知用量用空值或文档中的明确口径表示。
- 把 `pytest-asyncio` 写入 README 所述的安装依赖，使 `python -m pytest -q` 能跑完全部用例。补上可运行的 curl 示例，覆盖流式、结构化、模板、审计、重试和限流。
