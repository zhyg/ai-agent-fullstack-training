# 第一周作业反馈

学员：我是智仔 G20261786010584

**1. 作业等级：良好（69分）**

**2. 作业优点**

- 同一接口可路由 Chat Completions 和 Anthropic Messages；使用独立配置，两种协议均完成 DeepSeek 官方真实调用和流式输出。
- 双协议门控验证收到正文后才释放终态，确认不是收齐后伪流式；输出后的上游故障未触发重复生成。
- 模板发布、变量替换、显式引用新旧版本及缺失项报错均通过；模板输出模式能校验非法 JSON 和字段类型。
- 183 项学生离线测试通过，故障注入能触发失败断言；请求链路、HTTP 失败和重试尝试均有可关联记录。

**3. 作业不足**

- 缺少按模型独立限流，尚不能提供本地超限 429、模型隔离和配额恢复能力。
- 单独传入 response_format 时，非法、空和截断 JSON 仍返回成功；Messages 适配器还会丢弃该约束，不能靠一次合法输出证明格式保证。
- 空角色事件提前触发 TTFT；显式 SSE 错误被记为成功；Messages 用量归一化丢失上游缓存分类。
- 重试采用固定等待而非指数退避；普通参数错误也重复请求三次。
- 缺少面向项目使用者的 README 和 curl 示例，依赖清单遗漏入口启动所需的 uvicorn，干净环境无法直接执行启动命令。

**4. 改进方案**

- 实现模型独立配额，降低测试阈值后验证 A 超限返回 429、B 仍可用，并等待声明窗口验证 A 恢复。
- 让统一 response_format 同时驱动协议约束与本地校验；补测两协议的正常、非法、空、截断 JSON，确认失败不返回成功。
- 只在首个非空正文或明确声明的推理增量计时，非流式 TTFT 留空；保留缓存分类，并断言 SSE 错误落为失败记录。
- 实现有上限的指数退避，将参数与鉴权错误排除重试；用受控上游核验等待序列及实际请求次数。
- 补全安装、双协议配置、启动及 curl 示例，将启动依赖列全；在干净环境复跑已有测试和上述异常验收。
