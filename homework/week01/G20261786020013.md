# 第一周作业反馈

学员：G20261786020013（雷锋剑，第一次提交）

**1. 作业等级：优秀（85分）**

**2. 作业优点**

- 作业分支实现了 Responses、Messages 两种协议；本次用 DeepSeek 官方接口完成两个模型的普通、流式和 JSON 真实调用。
- 模板支持存储、变量替换和版本引用，更新后仍能把旧版模板正确送入模型请求，缺失模板、版本和变量也有明确错误。
- 双模型 SSE 门控测试确认内容能在生成结束前到达；正文后出现网络异常或错误事件时，没有重新生成或重复输出。
- 自带 39 个测试、16 项离线验收均通过；注入故障后验收脚本能报告失败。模型限流隔离和配额恢复也已验证。

**3. 作业不足**

- 结构化输出会接受从截断正文中提取出的局部 JSON，却把非法原文作为成功内容返回；不存在的 Schema 引用还会产生未封装的 500。
- 上游未发送成功终态就结束连接时，网关仍返回正常结束并记录成功；中文字符跨网络块时还会出现乱码。
- 重试耗尽、结构修复失败时，账本丢失重试次数或修复用量；未知模型失败没有记录，未提供用量也直接显示为零。
- 重试等待在达到配置上限后还会增加抖动；上游限流与网关本地限流使用同一个错误码，调用方无法可靠区分。
- 流式请求耗尽本地模型配额时，正文虽有错误事件，HTTP 状态却仍为 200，而不是 429。

**4. 改进方案**

- 只接受完整正文可解析的 JSON，或将提取结果重新序列化后返回；提交非法、空、嵌套截断正文及有效、无效 Schema 引用的回归证据。
- 要求收到协议成功终态才能记为成功，使用增量 UTF-8 解码；用门控、无终态 EOF、正文后断流和中文跨块测试复验。
- 在请求生命周期中持续保存尝试次数、修复次数和已知用量，失败也完整记账；未知值用空值或明确说明零的含义，并验证未知模型记录。
- 在加入抖动后执行等待上限约束，区分本地和上游限流错误码；用固定故障序列核对实际请求数、等待值与账本。
- 在建立 SSE 响应前完成本地配额检查，确保普通与流式超限均返回 HTTP 429，同时保留另一模型可用及配额恢复的测试。
