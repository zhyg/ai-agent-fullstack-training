# 第一周作业反馈

学员：G20261786020116（帕克）

**1. 作业等级：优秀（97分）**

**2. 作业优点**

- Responses 与 Messages 适配器具有不同路径、请求结构与解析逻辑；独立配置下，两协议均以 DeepSeek 官方 Flash 完成真实普通及 JSON 调用。
- 教师门控验证中，两协议正文均在终态释放前到达；输出后断流均返回错误，且没有重新请求上游。
- 模板 v1/v2 可分别引用，旧版本内容确实进入上游请求；缺模板、缺版本及缺变量均返回明确错误。
- 非法、空、截断及不符 Schema 的模型内容均被拒绝；学生脚本 14 项通过，模型隔离限流及实际等待 60 秒后的恢复也已验证。

**3. 作业不足**

- 真实接入证据尚不完整：Pro 未获得有效成功响应，两协议真实流式也未完成成功验收；这些环境相关阻塞不扣代码分，成绩暂评。
- 上游拒绝结构化格式并返回 400 时，网关统一返回 502，未保留明确的客户端错误状态。
- 调用记录保留输入、输出及细分类别，但遗漏总 Token 数，无法直接查询本次总用量。
- HTTP 重试的抖动可能超过该轮指数等待上界；固定随机种子实测前两次等待约 0.284、0.552 秒，超过 0.25、0.5 秒。

**4. 改进方案**

- 在上游可用时补交两个实际模型的普通、流式成功证据，保留协议路径、请求标识、用量及延迟；流式须有有效正文与成功终态。
- 区分上游参数错误与服务故障，将不支持格式的 400 封装为统一 4xx；以受控上游拒绝用例复验。
- 在记录与统一响应中增加 total_tokens，注明分类是否属于总量子集、失败用量是否完整；用已知输入输出用量核对。
- 将抖动约束在每轮指数上界以内；保留当前实际四次尝试上限，用固定随机种子记录等待值并验证边界。
