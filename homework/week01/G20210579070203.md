# 第一周作业反馈

学员：G20210579070203（灿若繁星先生）

**1. 作业等级：优秀（96分）**

**2. 作业优点**

- Responses 与 Anthropic Messages 两种上游协议均经教师官方真实调用验证，普通请求、SSE 和完整 JSON Schema 输出可用。
- 门控测试确认正文在终态前增量到达；已输出正文后断流会返回明确错误，且不会重新请求导致内容重复。
- 模板新旧版本可显式引用，缺模板、版本和变量均明确报错；非法、空和截断 JSON 在修复仍失败后返回错误。
- 指数退避、有限尝试、按模型限流隔离及配额恢复均经实测；学生离线脚本 79 项测试通过，故障注入能检出失败。规则脱敏与跨块占位符还原是额外亮点，不另加分。

**3. 作业不足**

- Token 分类仍不完整：标准 Anthropic 流只在起始事件提供的输入、缓存用量会丢失；Responses 已提供的推理 Token 分类也未保留。
- 结构化修复发生多次已知消耗时，成功账本只记最后一次，修复失败则记为零，且未标注计量不完整，影响用量对账。
- 本地限流返回的 429 没有对应账本记录，无法按请求标识完整查询失败调用。

**4. 改进方案**

- 合并 Anthropic 起始与结束事件的用量，保留上游可用的推理分类；以起始输入 17、缓存 3、结束输出 5 的分离事件及含推理用量的 Responses 响应复验。
- 累积各次已知调用用量，或明确展示每次尝试及不完整计量状态；验证两次输入/输出分别为 13/7、5/3 时，成功和失败终态都不丢已知消耗。
- 将本地限流失败纳入请求生命周期记账；耗尽一个模型配额后，用返回的请求标识查到 429 记录，同时确认另一模型仍可用。
