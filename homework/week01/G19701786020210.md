# 第一周作业反馈

学员：G19701786020210

**1. 作业等级：优秀（91分）**

**2. 作业优点**

- 同一入口 `POST /v1/llm` 按 model 分别接到 OpenAI Responses 和 Anthropic Messages。两条路径的请求地址、鉴权头和请求体都不同，官方接口上两个模型的普通调用、流式和结构化调用都已跑通。
- 流式以 SSE 逐块下发，已开始输出后遇到上游错误事件会结束为失败，不会把已输出内容再重试一遍。非法、空、截断 JSON 不会当作成功结果返回。
- 模板可保存多个版本，变量会替换后再进入上游请求；缺模板、缺版本、缺变量都返回明确错误。每次调用有 Token 分类、总延迟和流式首 Token 延迟，失败调用也有记录。按模型独立限流，超限返回 HTTP 429，配额能按令牌补充恢复。
- README 含启动步骤和 curl 示例。提交的验证脚本覆盖了六个功能点，本次复跑 19/20 通过，退出码为 1。未通过的一项是模型正文被截断，不是断言写错。

**3. 作业不足**

- 流式连接在已经收到正文后直接结束、没有成功终态时，仍被记成成功，用量记成 0。客户端无法从结束事件看出这次调用失败。
- 声明支持 JSON Schema 时，Schema 里引用了不存在的本地定义，服务进程会抛出未处理异常并退出，而不是返回入参错误。模型内容里的 NaN 能通过解析，但响应序列化时同样会变成未处理的 500。后者不影响本次得分，建议一并处理。
- 上游 400、401 等客户端错误被映射成 HTTP 502。本地重试次数本身有上限，但结构化校验失败发生在重试之外，已知用量也没有写入失败记录。
- 验证脚本只覆盖正常路径，没有断言断流、非法 JSON 和 Schema 引用错误。README 启动目录写成了 `homework`，与仓库里的 `chapter01-homework` 不一致。

**4. 改进方案**

- 流式读取结束时，如果没有收到成功终态，应向前端发送错误事件，并把这次调用记为失败。用“先发一个正文块再直接断开”的本地模拟确认，不能再出现成功结束事件。
- 在调用模型前解析 Schema。本地引用不存在时返回 400，并保留一条引用存在的对照请求，确认正常 Schema 仍可通过。响应序列化不要因 NaN、Infinity 变成 500。
- 上游 4xx 映射为明确的 4xx，或在统一错误体里与 5xx 区分开。结构化校验失败时保留本次已知用量，并确认这类失败不会把上游再请求一遍。
- 给断流、非法 JSON、缺 Schema 引用各补一条会失败的断言。把 README 的启动目录改成实际目录，再按文档从干净环境启动并复跑验证脚本。
