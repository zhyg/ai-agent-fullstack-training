# 第一周作业反馈

学员：G20258465020022（芝士嘉年华）

**1. 作业等级：良好（79分）**

**2. 作业优点**

- 统一接口能按模型路由，Chat Completions 与 Anthropic Messages 请求结构、响应解析确有差异；使用独立 DeepSeek 官方配置，两个模型的非流式与流式调用均成功。
- 双模型通过门控增量验证：终态尚未释放时已下发正文；传输异常会返回失败事件，输出后没有重新请求造成重复内容。
- 模板可显式引用两个版本，更新后旧版本仍可用；缺模板、版本和声明变量均明确报错，未请求上游。
- 依照 README 可安装启动；105 项离线测试及静态检查通过，教师注入错误端点后原测试能够检出失败。重试实测为三次尝试，等待呈指数增长。

**3. 作业不足**

- 按模型独立限流尚未实现，README 将其列为后续扩展；当前无法验证本地超限 429、模型隔离及配额恢复，核心要求仍未完成。
- 统一入口拒绝题目要求的 response_format；已有 response_scheme 能校验 JSON，但提取围栏内容后仍在成功响应的正文中保留非 JSON 原文。
- 流式 TTFT 在角色元数据到达时即计时，早于首个有效正文；缓存、推理 Token 分类丢失，Anthropic 缓存场景还会少计总量。
- Anthropic 流内错误事件被忽略，随后输出成功终态并记录成功；这与已经能正确处理的传输异常不同。
- 上游参数错误 HTTP 400 被包装为 HTTP 502，调用方无法通过状态码正确识别不可重试的请求错误。

**4. 改进方案**

- 增加可配置的模型独立配额；用低阈值验证模型 A 返回本地 429、模型 B 仍可调用，等待窗口后 A 恢复。补充此项验收脚本。
- 支持统一 response_format 并映射到双协议；对提取后的 JSON 重新序列化为成功正文，保留本地 Schema 校验，回归非法、空、截断及围栏输出。
- 首个非空正文到达时才记录 TTFT；保留上游实际提供的缓存、推理分类并按协议计算总量，以延迟元数据夹具和非零缓存夹具复验。
- 显式识别流内 error 事件并返回失败、记录失败，不再追加成功终态；验证已输出正文时仍仅调用一次上游。
- 将上游参数错误映射为统一的明确 4xx，并保留不可重试行为；以模拟 400 验证状态、错误结构及实际请求次数。
