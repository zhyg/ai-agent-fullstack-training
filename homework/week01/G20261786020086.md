# 第一周作业反馈

学员：周一打哈欠（G20261786020086）

**1. 作业等级：优秀（91分）**

**2. 作业优点**

- 同一入口按模型别名把请求送到两种不同协议：DeepSeek v4 pro 走官方 Responses API，DeepSeek flash 走官方 Anthropic Messages API。普通调用和流式调用都已用真实模型跑通，响应里的模型名和请求号是网关自己的。
- 流式以 SSE 增量下发。门控模拟中，内容块在终态之前已经到达客户端；输出开始之后断流会记为失败，不会把已发出的正文再生成一遍。
- 结构化输出在成功返回前会做 JSON 解析和 schema 校验。非法 JSON 与字段不符都会返回明确错误，而不是把坏正文当成成功。围栏和尾逗号有本地修复，修复后会重新校验。
- 提示词可以存版本、替换变量，并显式引用旧版本。缺模板或缺变量会返回明确错误，不会把未替换的占位符发给模型。限流按调用方加模型分桶，一个模型超限不影响另一个，超限返回 HTTP 429，配额会恢复。
- README 有启动步骤和 curl 示例。提交的 pytest 覆盖路由、流式、结构化、模板、观测、重试和限流；在补上 README 要求的 MiniMax 密钥后，206 项全部通过。

**3. 作业不足**

- 作业要求的统一字段是 `response_format`。现在的入口不接受这个字段，会直接返回 400。等价能力放在 `output_schema` 上，两种协议的结构化调用本身可用，但调用方必须改用另一套字段。
- 默认配置里的两个 DeepSeek 别名指向本机 mock，不是官方接口。按 README 原样启动，不能直接证明两个模型都接到了真实上游。本次评测是另行改配置后才完成真实调用的。
- 流式首 Token 延迟会把空增量算进去。心跳不会被误计，但空的正文增量会把首 Token 时间提前。README 也没有写明默认开启思考时，首 Token 以推理还是正文为准。
- 关闭结构化的严格校验后，非法 JSON 仍会以 200 成功返回。这是代码里写明的行为，但和“返回内容必须是合法 JSON”不完全一致。
- 上游 400 被映射成 502，调用方不容易区分自己的参数错误和上游拒绝。Anthropic 适配器在默认思考模式下，强制工具调用会被官方接口拒绝；不关闭思考时，这条协议的结构化调用到不了本地校验。

**4. 改进方案**

- 统一入口接受作业要求的 `response_format`，并映射到现有的 `output_schema`。用同一份 JSON 约束分别请求两个模型，确认不再因为字段名被 400，且成功正文仍是合法 JSON。
- 在 README 写明真实上游的 Base URL、模型标识和密钥变量，并给出一条不依赖 mock 的启动步骤。用两个官方模型各完成一次普通调用、流式调用和结构化调用，把脱敏后的请求路径和响应留在验证记录里。
- 首 Token 只从第一个非空有效内容块计时，并在文档写明思考模式下以正文还是推理为准。用“先心跳或空增量、再延迟正文”的模拟确认计时落在正文上。
- 即使关闭严格 schema 校验，也不要把非法、空或截断的 JSON 当成功。补一条关闭严格校验后的回归用例，确认此时返回明确失败。
- 把上游 4xx 与网关自己的 502 区分开。Anthropic 结构化路径在官方默认思考模式下应能完成，或在不支持时于入口返回明确的 4xx，而不是等上游拒绝后再包成 502。
