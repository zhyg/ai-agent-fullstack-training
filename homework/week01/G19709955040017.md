# 第一周作业反馈

学员：文森特没有眼泪（G19709955040017）

**1. 作业等级：优秀（86分）**

本次为基于已确定证据的暂评分。

**2. 作业优点**

- 在不修改业务源码的情况下，使用教师独立配置，DeepSeek 官方 Flash／Responses 与 Pro／Chat 两模型均完成真实普通、JSON 和流式调用；统一 Responses 入口的非流式响应可用。
- 双协议受控门控测试证明内容在上游结束前到达；文本输出后断流不重试，未出现重复生成。
- 模板新旧版本均能正确替换变量并进入上游请求；缺失模板、版本和变量有明确错误。
- 重试实际请求次数符合首次加三次上限，400／401 不重试；模型独立限流返回 429，补充令牌后恢复。离线脚本 14 项、网关测试 316 项通过。

**3. 作业不足**

- 原配置中的 MiMo 模型未做真实验收，本次仅验证了官方 DeepSeek 替代配置；该证据缺口不按代码缺陷扣分，不能据此宣称原供应商组合全部通过。
- `json_object` 对非法、空及截断 JSON 仍返回成功；Schema 模式虽能拒绝错误内容，却会把带 Markdown 围栏的原文成功返回，正文并非合法 JSON。
- 同一 Responses 入口的 Chat 上游流仍输出 Chat 事件，调用方需区分协议；上游无成功终态便结束时也未明确报错。
- 流中断及错误事件被账本记为成功，本地限流等入口失败没有调用记录，影响失败统计和排查。
- Responses 推理 Token 分类丢失，部分非流式账本分类也丢失；非流式完整响应耗时被填入首块延迟，易与真实首 Token 延迟混淆。

**4. 改进方案**

- 补交原配置双模型的脱敏真实调用证据，或明确以官方 DeepSeek 双协议配置作为交付配置，记录模型映射、请求标识和用量。
- 对所有结构化模式校验最终返回正文；提取围栏内容后应返回合法 JSON。加入非法、空、截断及修复仍失败的回归验收。
- 将 Chat 流转换为统一 Responses 事件；显式识别正常终态、错误事件与无终态结束，并验证输出后始终不重试。
- 让流式失败进入失败落账路径，入口拒绝也记录请求标识、状态及原因；分别查询普通失败、断流和 429 的记录确认结果。
- 保留两协议的推理／缓存分类，避免渲染后再次解析丢字段；非流式首 Token 延迟置空或单列完整响应耗时，并对照上游用量与门控时间验收。
