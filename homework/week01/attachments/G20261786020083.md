## D. 扣分证据（固定提交行号）

### D1 流式模型限流未返回 HTTP 429：限流项扣1分

- 触发：`glm.rpm=1`，先普通调用耗尽，再 `stream=true` 请求同模型。
- 期望：本地超限返回 HTTP429；另一模型继续可用。实际：普通429、另一模型200，而流式HTTP200，terminal为failed/GATEWAY_RATE_LIMITED。
- 命令：`uv run --frozen pytest /tmp/g83-evidence/test_teacher.py -q -s -k F10_F11 --asyncio-mode=auto`。
- 证据：`teacher-final.log` 中 `F10 stream HTTP 200` 和 `F11 real elapsed 60.2s recovery 200`。实现位置：`src/api/src/llm_gateway_api/app.py:299–315` 在 executor 执行前创建StreamingResponse；`src/core/src/llm_gateway_core/execution.py:274–281` 才进行模型限流。
- README.md:136 明确披露200行为，但作业已明确要求超限429，文档不能替代要求。保留独立计数、普通429及恢复得分；不再从流式/文档/错误项扣。

### D2 抖动使退避最终值越过cap：重试项扣1分

- 触发：单候选持续503，initial_delay_s=max_delay_s=0.02，固定随机返回1.5（实现允许区间上界）。
- 期望：实际等待不超过配置cap 0.02秒；实际：四次请求、三次等待均0.03秒。指数增长和次数上限本身可用，故仅部分扣分。
- 命令：`uv run --frozen pytest /tmp/g83-evidence/test_teacher.py -q -s -k backoff_cap --asyncio-mode=auto`。
- 证据：`teacher-final.log` / `teacher-extra.log` 的 `DEFECT backoff configured cap=0.02 actual waits= [0.03, 0.03, 0.03]`；固定源码 `src/core/src/llm_gateway_core/execution.py:184–196`，min(cap, exponential)之后再乘random.uniform(0.5,1.5)。
- 这也违反README声明的不超过max_delay_s；不因四次尝试扣分（首次+重试3次为标准允许解释），不重复扣测试分。
