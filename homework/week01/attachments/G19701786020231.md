### D1：上游鉴权错误映射为 502（已确认）

- 所属评分项：统一错误与重试 → 错误结构/状态映射。
- 触发条件：上游返回 401 或 403，JSON `{"error":{"message":"controlled rejection"}}`。
- 预期：明确统一 4xx 错误；不可重试。
- 实际：HTTP 502，code=UPSTREAM_AUTH_ERROR、retryable=false，每个场景仅一次上游调用。
- 复现：`supplement.py` 的 `upstream-401-mapping` / `upstream-403-mapping`。源码 `source/app/errors.py:155–158` 采用默认 502。
- 扣分：**1**。严格采用第 8 节上游 4xx→502 的同类口径；两种状态不叠扣，也不扣统一接口和不可重试子项。

### D2：无效 Schema 本地引用导致内部 500（已确认）

- 所属评分项：统一错误与重试 → 错误处理。
- 触发条件：统一入口 response_format 为 `{"type":"json_schema","json_schema":{"schema":{"type":"object","properties":{"city":{"$ref":"#/$defs/missing"}}}}}`；受控上游正文 `{"city":"Singapore"}`。
- 预期：明确的无效 Schema/引用 4xx，而非内部 500。
- 实际：HTTP 500、code=INTERNAL_ERROR，包含 PointerToNowhere 引用解析异常；对照 `#/$defs/city` 配置有效 `$defs` 时 HTTP 200。
- 复现：`badref` / `goodref`；异常堆栈在 `logs/supplement.log` 与 `logs/supplement-gateway.log`。源码 `source/app/adapters/base.py:128–151` 仅检查 schema 结构，没有拦截引用解析异常；`source/app/service.py` 将其兜底为 INTERNAL_ERROR。
- 扣分：**1**。按第 8 节本地引用示例，不在结构化子项重复扣分。

### D3：正向抖动超过当次等待上限（已确认）

- 所属评分项：统一错误与重试 → 指数退避。
- 触发条件：base=0.5s、cap=0.5s、jitter=0.2s，受控随机来源返回合法上界 0.2；前两次失败、第三次成功。
- 预期：第 n 次等待不超过 `min(cap, base*2^(n-1))`，两次均 ≤0.5s。
- 实际：等待记录 **[0.7, 0.7]**，共 3 次尝试。只注入随机值和记录 sleep，不修改业务公式。
- 复现：`backoff-cap`；源码 `source/app/retry.py:46–49` 先 min 后加抖动；README 也明示该公式。
- 扣分：**1**，按本批统一口径；尝试次数与轨迹正常，保留相应分值。
