## 扣分证据与最小复现

下列源码行号均相对固定提交的 `week01/llm-gateway/`；包内 `student-source/` 可核对。完整命令见 `REPRODUCE.md`，一次执行 `python /tmp/huncidd-grade/teacher_run.py` 可重现全部受控项。

### D1 无成功终态的 EOF 被当作成功（流式 -2）

- 触发：`POST /teacher/control {"mode":"eof"}`，再对任一模型调用统一入口 `stream=true`。上游仅输出 alpha 后结束，无 response.completed/message_stop。
- 预期：可识别失败、账本 error、不重新生成；实际：alpha 后 finish_reason=stop、[DONE]，账本 success，上游1次。
- 证据：`teacher-results.json` 的 `F02 deepseek-v4-pro eof` / `F02 deepseek-v4-flash eof`；请求 ID 分别 `req-29fa8778e25248d99403448914d2ffc1`、`req-72eedf16d8e3440399fbeba5a54c2749`。
- 源码：`app/adapters/responses.py:145–146`、`app/adapters/messages.py:179–191` 在未收到终态时补造 done。两个协议同根因只扣一次；不再扣账本状态分。此处是无终态中断，不是正常 length 截断建议项。

### D2 结构校验失败丢失已知 Token（可观测性 -2）

- 触发：`POST /teacher/control {"mode":"invalid"}`，统一入口带 response_format=json_object。上游明确返回 input17/output9/total26，Responses 另有 cache4/reasoning3。
- 预期：422错误且失败记录保留已知用量；实际：正确422，但所有 Token 均0。
- 证据：`F07-known-usage-on-failure` 两模型；请求 ID `req-8d3eccd0e8e746f790788f766d25e7cc`、`req-6f38562eedb545bd96975438bd0afb1b`。fixture 的真实返回值见 `teacher_server.py` usage 和 handler。
- 源码：`app/services/gateway.py:172–174` 先校验再赋 usage；抛错后 `:361–377` 用默认状态落账。不是“上游未提供”的0值约定，不重复扣结构化输出分。

### D3 未知模型失败无账目（可观测性 -1）

- 触发：统一入口 model=unknown；用响应头/错误体 request_id 查询 `/v1/calls/{id}`。
- 预期：明确错误且存在失败记录；实际：404 MODEL_NOT_FOUND，查询404 CALL_NOT_FOUND，上游0次。
- 证据：`A04` 与 `F07-unknown-failure`；原请求 ID `req-05868b1a7eff449abb2829fec65b624f`。
- 源码：`app/services/gateway.py:82` 的路由在 `:89` 的异常记录范围之前。路由本身正确，不再扣统一接口分；不扩展到鉴权/请求体校验等无模型调用场景。
