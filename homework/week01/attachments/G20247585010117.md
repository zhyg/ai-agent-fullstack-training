### 两个模型真实调用与协议

同一 `POST /v1/invoke`：

- `deepseek-v4-pro`：HTTP 200，provider `openai-responses`，mode `live`，正文 `pong`，用量 input 91 / output 28 / cached 0 / total 119，attempts 1。上游路径 `/v1/responses`，Bearer 鉴权，请求体含 `input`、`max_output_tokens`。
- `deepseek-v4-flash`：HTTP 200，provider `anthropic-messages`，mode `live`，正文 `pong`，用量 input 38 / output 21 / total 59。上游路径 `/v1/messages`，`x-api-key` 加 `anthropic-version: 2023-06-01`，请求体含 `messages`、`max_tokens`。

协议差异由受控探针记录，不依赖模型名。状态：已确认。

未知模型 `no-such-model`：HTTP 400，`unsupported_model`，未调用上游。

### 流式

- 两个模型真实 `stream=true`：Content-Type `text/event-stream`，事件 `start, delta, delta, usage, done`，拼接正文 `pong`。pro 首事件 2.9 ms、末事件 2924.4 ms；flash 首事件 3.8 ms、末事件 905.9 ms。日志 TTFT 分别为 2833.05 ms 和 889.68 ms。
- 门控上游先发一块并暂停终态：客户端 0.012 秒收到 delta，终态释放后 0.414 秒收到 done，间隔 0.402 秒。状态：已确认增量下发。
- 已输出 delta 后的上游 error 事件：客户端收到 `start, delta, error`，上游只被调用 1 次，没有重试出第二段正文。状态：已确认。
- 上游发出一块后直接 EOF、没有成功终态：客户端仍收到 `start, delta, usage, done`，日志 `ok=true`。状态：已确认缺陷。
- 心跳和空增量后才有正文：TTFT 记在正文 delta，没有把心跳当首 Token。状态：已确认。

### 结构化

- 统一字段 `response_format.type=json_object` 加 schema。Responses 上游收到 `text.format.type=json_schema`；Anthropic 上游收到 `tools` 和 `tool_choice={"type":"tool","name":"structured_output"}`。受控上游下两边都返回合法 JSON。
- 真实 Responses：HTTP 200，`output.json={"word":"pong"}`。
- 真实 Anthropic：HTTP 502，`upstream_error`，上游原文是 thinking 模式不支持该 `tool_choice`。直接请求官方接口时，`thinking: disabled` 或 `tool_choice: auto` 可以返回 tool JSON；学员适配器没有这两种路径。状态：已确认缺陷。
- 非法 JSON、空正文、截断 JSON、JSON 数组：HTTP 502，`upstream_invalid_json`，只请求上游 1 次。围栏 JSON 由归一化直接拒绝。`strict=false` 时缺字段的合法对象仍成功，符合文档“只解析 JSON”。状态：已确认。
