## 验证结果

- 启动：按 README 的 conda/`homework` 路径不能直接复现。在 `chapter01-homework` 用独立 venv 安装 `requirements.txt` 后，`uvicorn gateway.main:app` 可启动。`GET /healthz` 200。
- 两个模型真实调用与协议：已验证。捕获代理只记录路径和鉴权头名称，密钥已脱敏，再转发到官方接口。
  - pro：`POST /v1/responses`，`Authorization: Bearer`，请求体含 `input`、`max_output_tokens`、`text.format`。普通调用返回 `PONG`，`finish_reason=completed`，usage input 87 / output 30 / reasoning 27。
  - flash：`POST /anthropic/v1/messages`，`x-api-key` + `anthropic-version: 2023-06-01`，请求体含 `messages`、`max_tokens`、`thinking.type=disabled`。普通调用返回 `PONG`，`stop_reason=end_turn`，usage input 8 / output 2。
  - 流式：两模型均为 `text/event-stream`，先 `content.delta` 再 `response.completed`。短回复首块与结束几乎同时（pro 2127.0 / 2127.7 ms，flash 1006.8 / 1007.5 ms），只能证明不是收完再伪造，不能单独证明门控增量。门控模拟未做，不因此扣分。
  - 结构化：两模型 `json_schema` 均返回 `{"city":"北京"}` 且 `parsed` 通过。`json_object` 两模型均返回 `{"ok": true}`。Responses 走 `text.format`，Anthropic 走 system 指令加本地校验。
- 提交方验证脚本：`python tests/verify.py --port 8010`，退出码 1，19/20。失败项是「Prompt 缺省引用最新版本（v2）」：HTTP 200，版本解析为 v2，正文为 `网关作业 第二<|endoftext|>`，断言要求正文含 `BETA-7`。这是模型输出被截断，网关版本解析正确。脚本最后仍写了 `verification_report.md`（评测后已从学员工作树还原，未改学员源码和测试断言）。
- 教师补测：本地模拟上游，见下表。
- 未验证项目及原因：
  - 未做门控流式（先发正文、暂不发终态、确认下游已收到再放终态）。现有短回复流式不能单独排除缓冲。
  - 未验证心跳事件是否被计为 TTFT。实现只把非空 `text` 增量计为 first token，空增量不会触发；心跳本身未注入。
  - 未验证客户端主动断开后是否产生第二次上游请求。
  - 学员验证脚本里依赖真实模型的那一项本次未稳定复现通过，不把模型截断算作代码缺陷。

## 待修复问题

1. 问题与评分项：流式无成功终态的 EOF 被当成成功（流式输出 / 终止与错误处理）
   - 触发条件：上游已发送一个正文增量后关闭连接，没有 `message_stop` / `response.completed`。
   - 预期结果：客户端能识别失败，审计记为失败。
   - 实际结果：HTTP 200 SSE，事件为 `content.delta` 后 `response.completed`；trace `status=success`，usage 全 0，`first_token_ms=2.8`。
   - 复现命令与证据：本地模拟 `always-hang-after-delta`，见 `probes/run_probes.py` 与 `logs/probe-eof.txt`。
   - 扣分：2

2. 问题与评分项：上游 4xx 映射为 502（统一错误与重试 / 错误结构、错误码与状态映射）
   - 触发条件：上游返回 400 或 401。
   - 预期结果：统一错误结构中的状态或错误码能表达客户端错误，而不是一律 502。
   - 实际结果：HTTP 502，`upstream_bad_request` / `upstream_auth`。401 与 400 均只请求 1 次，次数上限不另扣。
   - 复现命令与证据：`logs/probe-retry.txt`。
   - 扣分：1

3. 问题与评分项：失败调用丢失已知用量（可观测性 / 失败调用记录）
   - 触发条件：上游已返回 usage，随后结构化校验失败；或流式已产生用量后失败。
   - 预期结果：失败记录保留已知用量，未知再标 null。
   - 实际结果：`gateway.py` 错误分支 `usage: None`。`invalid_json` trace 的 usage 为 null。
   - 复现命令与证据：`logs/probe-json.txt`。
   - 扣分：2

4. 问题与评分项：README 启动指南不可按原文复现（源码、README 与验证脚本）
   - 触发条件：按 README「cd homework」及 `/opt/homebrew/.../geek/bin/python` 启动。
   - 预期结果：文档中的目录和命令可在干净环境执行。
   - 实际结果：仓库目录是 `chapter01-homework`，解释器路径是作者本机 conda。依赖列表本身完整，独立 venv 可安装并启动。
   - 扣分：3

5. 问题与评分项：不存在的 Schema 本地引用打崩进程（评语级待修复，不另扣分）
   - 触发条件：`response_format.type=json_schema`，`$ref` 指向不存在的 `#/$defs/Missing`。
   - 预期结果：4xx 入参错误，进程继续服务。
