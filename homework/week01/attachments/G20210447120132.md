## 待修复问题与独立扣分复现

1. **json_object 未验证模型正文（结构化 -3）**
   - 触发：`teacher_checks.py` F04 两模型 json_object 的 invalid / empty / truncated。
   - 预期：失败或修复后重新验证，不以成功返回非法 JSON；实际：HTTP 200，内容分别为 `not json`、空串、`{"ok":`。
   - 根因与行号：`services/structured.py:14-23` 仅 json_schema 返回校验 Schema，`services/gateway.py:172-176` schema 为空便直接成功。Schema 分支能拒绝，本项不扣修复能力分，也不按六次输入重复扣分。
   - 证据：`controlled-results.json` 对应 F04 项，捕获次数和响应可直接重放。

2. **流内错误记成功（流式 -2）**
   - 触发：F02 `event_error`，先输出 GATE，随后协议错误事件并 EOF。
   - 预期：明确失败终态、账本 error；实际：两协议都将错误传出，但账本 success/200。ReadError 对照正确记录 error 且只实发一次。
   - 行号：`services/gateway.py:282-327` 转译/透传后无错误状态检查便 `record_success`、completed=True；`375-377` 以 completed 设置成功。
   - 证据：`controlled-results.json` 两个 F02-event_error 的 lines/ledger/calls。只在流式项扣，不再次扣可观测。

3. **TTFT 取首字节（可观测 -2）**
   - 触发：F01 心跳立即发送，正文延后120ms。
   - 预期：第一非空有效内容的到达延迟；实际：记录0.9–1.1ms，而客户端第一正文123.95–128.14ms，误把心跳作为首 Token。不是用客户端网络耗时直接代替服务端TTFT，而是依靠明确120ms门控对照。
   - 行号：`services/gateway.py:259-262` 在解析事件前任何 chunk 都赋 first_token_ms。
   - 证据：`controlled-results.json` F01 两项的 first_content_seconds 与 ledger.first_token_ms。

4. **本地限流失败未记录（可观测 -1）**
   - 触发：`supplement.py` 连续 A、A、B 三次请求。
   - 预期：成功及两个429均可关联记录；实际：200/429/429，但账本仅1行成功记录。
   - 行号：`api/routes.py:24-36` 限流先于 gateway 事件创建；`services/gateway.py:94-109` 才创建事件。
   - 证据：`supplement.json` requests 与 ledger。此处扣缺账，不为同一请求的限流隔离重复扣分。

5. **公共桶破坏独立模型额度（限流 -2）**
   - 触发：默认 burst=2、模型A/B各burst=1，依次请求A、A、B；均为原配置支持的合法值。
   - 预期：A200/A429/B200；实际：A200/A429/B429，B首次请求被 this caller 公共桶拒绝，仅1次上游调用。
   - 行号：`api/routes.py:24-36` 每次先扣公共桶，模型失败也不退还；`core/rate_limit.py:25-49` 实际桶键与额度更新。
   - 证据：`supplement.json` F10-global-coupling；大公共桶的 F10 与实等恢复 F11 为正对照。保留独立模型桶、429、恢复等已实现部分分。

6. **退避截顶后再抖动（重试 -1）**
   - 触发：固定 random.uniform 返回合法上界1.25，只替换随机源并捕获 asyncio.sleep，不改变业务实现。
   - 预期：等待不超 min(cap, base·2^n)；实际base=.08、cap=.5，等待 .1/.2/.4/.625/.625，超过 .08/.16/.32/.5/.5。
   - 行号：`services/gateway.py:453-456`。
   - 证据：`supplement.json` F08-backoff-injected-random；实际请求间隔和次数另由 F08/F09 验证。只扣等待上限1分，不扣已通过次数及不可重试处理。
