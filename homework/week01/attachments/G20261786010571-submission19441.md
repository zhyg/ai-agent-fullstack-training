## 待修复问题

1. 流式失败丢失已知用量（可观测性，失败调用记录，扣 3）
   - 触发条件：流式已收到带用量的增量后断流，或无成功终态结束。
   - 预期结果：失败审计保留已知用量，并用标记表示缺失部分。
   - 实际结果：`stream_with_fallback` 与 `responses_stream_with_fallback` 失败分支写入 `_empty_usage()`，审计 input/output/reasoning 均为 0，`usage_unknown=true`。客户端仍收到已输出正文。
   - 复现：`.amp/in/orb-backup/grading-scripts/recheck_extra.py` 的 `STREAM_FAIL_USAGE`：200、failed、`upstream_stream_failed`、in 0、out 0、unknown True，正文含“已经输出”。
   - 位置：`app/services/gateway.py` 失败终态 `build_trace`。
   - 扣分：3。不在流式项重复扣，因为失败已被识别，且该错误没有记成 success。

2. 正向抖动超过当次退避上限（统一错误与重试，指数退避，扣 1）
   - 触发条件：`jitter>0`，计算第 n 次重试等待。
   - 预期结果：等待不超过 `min(cap, base·2^(n-1))`。配置注释写 `base * 2^n + jitter`，即上限为该值。
   - 实际结果：`backoff_delay` 返回 `base * 2^attempt + random.uniform(0, jitter)`。200 次抽样中，attempt 0/1/2 的最大值分别为 0.5997、1.0993、2.0993，均超过 0.5、1.0、2.0。
   - 位置：`app/services/gateway.py` `backoff_delay`；`config.example.yaml` retry 注释。
   - 扣分：1。重试过程可验证，不另扣。

3. 自有入口拒绝 `response_format`（统一接口与统一结果，合计扣 4）
   - 触发条件：`POST /v1/llm` 带作业字段 `response_format`。
   - 预期结果：统一入口接受该字段，或映射到协议实际写法。
   - 实际结果：422 `extra_forbidden`。等价字段 `response_schema` 可用；`/v1/chat/completions` 接受 `response_format`，`/v1/responses` 接受 `text.format`。双协议结构化已验证，不在结构化项再扣。
   - 扣分：4。本批同类尺度：统一入口拒绝作业要求的 `response_format`，另有等价字段且双协议结构化可用，正常流程扣 4；已验证的解析和失败处理分保留。路由 4、双协议 4 不变。结构化输出仍为 10/10。

4. 示例配置的备用模型不能走专用 Responses 入口（启动指南，扣 1）
   - 触发条件：按 `config.example.yaml` 调用 `POST /v1/responses`，model 为 `general-backup`。
   - 预期结果：若 README 把两个模型都列为可走 Responses 的示例，应能调用或事先写明只支持已启用模型。
   - 实际结果：示例 `supports_responses: false`，入口 400 `responses_unsupported`。统一入口的 Chat 协议不受影响。评测配置打开开关后的真实成功不能代替示例配置。
