# 第一周作业反馈

学员：Vita（G20210607020285）

**1. 作业等级：优秀（83分）**

**2. 作业优点**

- 同一接口可路由 Chat Completions 与 Anthropic Messages；使用 DeepSeek 官方两个模型，本次普通、JSON、流式共六次真实调用均成功。
- 两个适配器均在上游终态尚未释放时下发正文；传输异常后能输出错误，且没有重新生成重复正文。
- 按模型独立限流有效：模型 A 超限返回 429 时 B 仍可调用，RPM 窗口与 TPM 令牌补充后均恢复。
- 提示词可存储并按版本引用，发布 v2 后仍能回引 v1；非法、空白及截断 JSON 的非流式请求会明确失败。

**3. 作业不足**

- 模板变量尚未替换：传入变量或遗漏变量时，`{{name}}` 都会原样进入上游请求。
- 流内错误事件未被正确识别；正文后收到错误事件或无成功终态结束时，客户端仍只收到结束标记。
- 可观测记录不完整：Messages 流式最终用量将已知输出 Token 清零，非流式上游失败没有调用账目，客户端响应也缺少与账目一致的关联标识。
- 已声明的 Schema 校验未落实枚举和数值边界；上游参数错误虽未重试，却统一变成 502。
- 已有测试未同步新的服务构造参数，32 项中 23 项报错，不能作为六项能力已完成验证的依据。

**4. 改进方案**

- 在统一入口接收并渲染模板变量；缺变量时明确报错。验证不同变量会改变实际请求正文，且不外发占位符。
- 识别协议内错误及缺失成功终态，输出明确失败；保留已经通过的增量输出与输出后不重试行为。
- 合并 Messages 用量快照而非用零覆盖已知值；在失败路径补全账目，并贯通响应与日志的请求标识。用固定 13 输入、7 输出验证最终总量为 20。
- 落实已承诺的 Schema 约束和上游参数错误映射；将枚举越界、数值越界及上游 400 加入回归。退避抖动也应遵循指数等待上限。
- 更新测试初始化，重新运行单元测试及限流脚本，并补齐六项能力的有效断言；故障注入时应清晰报告失败，建议同时返回非零退出码。
