# 第一周作业反馈

学员：G20210447120132（fuyu-fwj）

**1. 作业等级：优秀（89分）**（暂评）

**2. 作业优点**

- 统一入口可按模型路由，受控请求证实 Chat Completions 与 Anthropic Messages 使用不同路径、报文及响应转换。
- 双模型 SSE 通过门控增量验证；正文输出后发生网络断流时，返回错误且没有重新生成。
- 模板可发布并引用新旧版本，变量替换正确；缺模板、版本或变量时明确报错，不请求上游。
- Schema 输出具备本地校验与有限修复，重试、用量分类和配额恢复有受控证据；学生端到端脚本在受控上游下 18 项通过。

**3. 作业不足**

- 两个模型的官方真实接入尚未验证成功：本次官方调用超时或返回服务繁忙，不能将受控测试视为真实验收通过；此环境限制不扣分。
- `json_object` 模式未做成功前校验，非法、空及截断 JSON 仍返回成功；Schema 模式能正确拒绝这些内容。
- 上游流内错误事件虽传到客户端，账本仍记为成功；首 Token 延迟又以心跳等首字节计时，本地 429 也未落账。
- 全局调用方桶会让模型 A 的请求耗尽模型 B 的可用额度，模型桶尚未实现端到端独立。
- 指数退避在截顶后再乘抖动，实际等待可能超过配置上限。

**4. 改进方案**

- 上游恢复后，补交两个模型普通、流式及结构化真实调用的关联标识、用量、延迟与协议证据，再复验暂评分。
- 对所有 JSON 输出统一解析校验，仅返回合法正文；复测非法、空、截断及修复后仍非法的返回值。
- 将流内错误标为失败，首 Token 只计有效非空内容，并在限流入口建立失败记录；用延迟心跳和本地 429 核对账本。
- 避免公共桶破坏模型配额隔离；验证 A 超限后 B 仍可调用，等待补充后 A 恢复。
- 在抖动后执行等待上限约束，固定随机源核对各次等待与实际请求次数。
