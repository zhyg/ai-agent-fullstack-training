# 第一周作业反馈

学员：之虎者也（G20261930010051）

**1. 作业等级：优秀（82分）**

**2. 作业优点**

- 同一入口可按模型路由到 Responses 和 Anthropic Messages 两种协议，已通过 DeepSeek 官方端点验证双模型普通调用及流式输出。
- 两个模型均完成真实结构化输出；显式 Schema 可正常使用，受控测试中非法、空及截断内容修复失败后返回明确错误。
- 模板支持变量替换和版本保留，旧版本引用有效；缺失模板、版本或变量时不会继续请求模型。
- 按模型独立限流及配额恢复验证通过；自带 13 项离线测试和真实验证脚本的 12 项检查均通过。

**3. 作业不足**

- SSE 错误事件或缺少结束事件时仍发送结束标记并记录成功；传输异常虽未重新请求，却也没有正确记录失败。
- JSON 校验提取了围栏内的对象，但成功响应仍返回带围栏的原文，不能直接解析；pro 的 json_object 请求还会生成官方端点不接受的 Schema。
- 用量只保存输入、输出，遗漏已提供的缓存、推理分类及修复前消耗；未知用量混用零值或未标注的估算，空增量提前触发首 Token 计时，部分失败没有账本记录。
- Responses 将多轮消息拼成字符串，丢失用户与助手的角色边界，可能改变对话含义。
- 上游参数错误被统一转成 502，非法 Schema 可触发未封装的 500；退避抖动直接加在指数等待上，会超过该次等待上界。

**4. 改进方案**

- 为流事件维护明确的成功终态，识别错误与提前结束，捕获传输异常；复测门控断流，确认客户端收到失败、账本记错且上游只收到一次请求。
- 将通过校验的 JSON 重新序列化后返回，完善 json_object 的协议映射；用围栏、非法、空、截断及真实 pro 请求回归，成功正文应能直接解析。
- 保留上游用量分类，累计修复调用的已知消耗，未知值和估算值明确标记；仅以有效内容计时，并验证模板、限流及重试失败均能查询记录。
- 用 Responses 的消息数组保留角色和顺序，以“用户—助手—用户”输入检查实际发出的请求体。
- 预先验证 Schema 并统一返回明确的参数类错误，保留上游可区分的错误码；控制随机数验证退避等待不超上界，同时保持每个上游最多首次加三次重试。
