# 第一周作业反馈

学员：梦幻若水（G20190343020090）

**1. 作业等级：优秀（96分）**

**2. 作业优点**

- DeepSeek 官方 Responses 与 Anthropic Messages 两条协议的普通、流式和 JSON 调用均实际成功，统一入口与模型路由可用。
- 双协议在门控终态释放前即可下发正文；输出后断流会明确报错、不重新生成，避免重复内容。
- 模板发布 v2 后仍可引用 v1，变量替换及缺失项错误处理正确；按模型限流隔离、额度恢复和指数退避均经受控验证。
- README 可复现启动，学生自带测试 178 项通过；教师注入错误响应后，测试能明确报告失败。

**3. 作业不足**

- 流式总延迟以最后一个正文增量为终点，遗漏等待终态的时间；门控测试实际约 405ms，记录约 101ms。
- 非流式上游返回错误时，虽有请求关联和失败日志，但总耗时为空，未进入耗时指标。
- 上游缺失 usage 时仍返回全零且标为 reported，与 README 的估算兜底说明不一致，容易误认为真实零消耗。
- Messages 结构化修复只记录最后一次返回的用量；前一次已知消耗没有累计或另行留账。

**4. 改进方案**

- 将流式总延迟终点改为成功终态、错误或关闭时刻，保留首正文 TTFT；用延迟终态门控测试核对完整耗时。
- 在非流式失败路径补记总耗时，触发上游 400 后检查关联日志及耗时指标，TTFT 仍应为空。
- 区分缺失用量与真实零用量；使用未知值或明确标注的估算，分别测试有、无 usage 两种响应。
- 保留修复各次尝试的已知用量，明确合计口径；用两次均有用量的修复场景核对日志和指标，补充回归测试。
