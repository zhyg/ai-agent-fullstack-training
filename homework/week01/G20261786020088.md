# 第一周作业反馈

学员：G20261786020088（。）

**1. 作业等级：良好（73分）**

**2. 作业优点**

- 两套上游适配器确实使用不同协议。换用明确的官方模型配置后，DeepSeek Flash 和 Pro 的普通、流式、JSON Schema 调用均已实测成功。
- 流式内容可以边生成边收到。人为控制终态和制造输出后断流时，已输出内容不会因切换候选而重复生成。
- JSON Schema 模式会校验正文，能拒绝非法 JSON、空内容、截断内容和字段类型错误。
- 有 SQLite 调用账本、候选尝试记录和请求标识；提交的后端 17 项测试、前端 5 项测试实际通过。

**3. 作业不足**

- 目前只有候选切换，没有同一上游的指数退避重试；限流按调用方共用额度，一个模型用完后另一个也被拒绝。
- `json_object` 实际没有启用约束或校验，非法、空和截断正文仍返回成功；上游直接结束流而不发终态时，也会被当成正常完成。
- 模板支持文件存储和变量替换，但没有交付清楚的版本引用、旧版保留用法；模板缺变量会返回未处理的 500。
- 可观测数据没有首 Token 延迟和缓存、推理分类；部分入口失败不入账，结构校验失败时已知用量也会丢失。
- README 缺少 curl 示例，依赖安装被未确定的 esbuild 构建授权配置阻断；现有脚本没有覆盖模板版本和流式首 Token 计量等验收场景。

**4. 改进方案**

- 为单个上游加入有上限的指数退避重试，并按模型分桶限流。验证前两次 503 后第三次成功、400 不重试，以及 A 超限不影响 B、窗口后恢复。
- 让 `json_object` 也经过 JSON 解析；分别记录成功终态、异常和意外结束。补测两种协议的非法、空、截断正文及输出后断流。
- 明确模板版本的存储和引用约定，补齐 v1、v2、再次引用 v1 的完整请求例子；将缺变量转为明确错误，不能直接报 500。
- 保存正文首 Token 时间、上游提供的缓存和推理用量，处理流式用量更新；补齐失败记录，并核对结构校验失败前已经消耗的 Token。
- 确定 esbuild 构建授权，补充可直接运行的 curl 和验收脚本；覆盖模板版本、缺项、计量及上述边界，明确真实调用与受控模拟的范围。
